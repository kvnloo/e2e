# @e2e-dev/desktop

## 0.0.2

### Patch Changes

- [#2255](https://github.com/e2e-inc/e2e/pull/2255) [`d4086b5`](https://github.com/e2e-inc/e2e/commit/d4086b54930c4ea00d14a799556384989bd1173d) Thanks [@KrzysztofMoch](https://github.com/KrzysztofMoch)! - Add `screen.scrollTo(edge)` and `locator.scrollTo(edge)`, which scroll the page or a list to its `'top'`, `'bottom'`, `'left'`, or `'right'` edge, as far as it goes. On the web the screen scrolls the page, or the pane under the viewport's center when the page does not scroll; a locator scrolls its node or the nearest ancestor that scrolls. A device drags until a drag moves nothing. The engine contract gains the `scrollTo` action kind, outside SPI v1, which the web and mobile engines declare, so both now need `@e2e-dev/core` and `e2e` 0.25.1 or newer; the desktop engine does not declare it, so `scrollTo` there fails with `UNSUPPORTED_CAPABILITY`.

## 0.0.1

### Patch Changes

- [#1953](https://github.com/e2e-inc/e2e/pull/1953) [`a2d0363`](https://github.com/e2e-inc/e2e/commit/a2d0363128c95288b8e43d50029dc7a14b40c002) Thanks [@kdy1](https://github.com/kdy1)! - New package: `@e2e-dev/desktop`, the desktop engine. `engine: desktop()` drives a native app on macOS through agent-desktop's accessibility commands: observation, the `screen` locators and actions, test ids, secret fills over stdin, masked screenshots, and the `desktop` fixture. The app runs in the background and gets only a few variables of the run's environment. The engine downloads its pinned agent-desktop release on the first run.

- [#2056](https://github.com/e2e-inc/e2e/pull/2056) [`53f5cf6`](https://github.com/e2e-inc/e2e/commit/53f5cf603180e258c126f9afb6159f1cdd55ecf0) Thanks [@kdy1](https://github.com/kdy1)! - `desktop()` fixes. `e2e run --headed` launches the app in the foreground. `selectOption` refuses an editable combo box, `press` refuses a key agent-desktop cannot press, and a screenshot that cannot mask a password field fails with `POLICY_DENIED`. A read retries instead of passing as an empty screen, and keys and clicks no longer land on a control or window other than the one meant. `desktop()` returns `DesktopEngine`, so a config that infers its type declares under pnpm.

- [#2091](https://github.com/e2e-inc/e2e/pull/2091) [`202f121`](https://github.com/e2e-inc/e2e/commit/202f1216673f16a194f42b10e1d6ff85671d1288) Thanks [@kdy1](https://github.com/kdy1)! - More `desktop()` fixes. `@e2e-dev/desktop` now needs `@e2e-dev/core` and `e2e` 0.25.0 or later: it reports the `readonly` state `toBeEditable` reads. A read on a locked screen, a read cut short, or one agent-desktop says may be retried reads again instead of passing as an empty screen or failing for good; a minimized window, a control with no size, and everything under a hidden node read as hidden. Window titles come from accessibility, so they are right without Screen Recording permission. Node ids stay put across partial and interactive reads, and a key goes to a look-alike field only when its name and developer id still match. Screenshots: one withheld for a password field fails with `POLICY_DENIED` (a window deeper than `maxDepth` too); `toHaveScreenshot` captures again after a capture that failed; agent-desktop's raw capture never stays in the system temporary directory; static text and a window locator count as in view. `desktop({ maxDepth })` takes 1 to 50, `desktop(null)` is refused, quit shortcuts such as `ControlOrMeta+q` are refused before focus moves, `press` reaches a window on another Space, and `app.open()` works again after a failed launch. The cleanup of a killed worker's state tells it from a later process with its id, in any time zone.

- [#2147](https://github.com/e2e-inc/e2e/pull/2147) [`1501cf1`](https://github.com/e2e-inc/e2e/commit/1501cf114344a97cdee8454b775eddc48672ce23) Thanks [@okwasniewski](https://github.com/okwasniewski)! - `app.url` takes a `file:` URL: one file on this machine, which a browser the engine launches opens with no server, such as `pathToFileURL('dist/index.html').href`. A host or a directory is `INVALID_APP_URL`. On such a target, `app.open`, `browser.goto`, and the agent's `navigate` take a `file:` URL only for a file in that file's directory or below it, with symbolic links resolved; a file outside it and any directory stay `POLICY_DENIED`, and so does every `file:` URL on a target whose app is not a file. When a link or a script in the page takes the browser outside that directory, no agent step, trace, or failure report is given the screen there, and the agent is sent no screenshot of a file app at all: `agent.assert` with `vision: true` judges from the tree, `vision: 'only'` is `POLICY_DENIED`, and neither `agent.assert` nor a failure keeps a screenshot. A `video` you turn on still records wherever the browser goes. A file has no site, origin, or readiness poll: frames that load another document stay out of observations, `environment` defaults to `'test'`, an `app.command` beside it needs `app.readyUrl`, and a `web()` target with a browser provider, `connect`, `headers`, or `basicAuth` refuses it. An engine opens a file app only when it declares `fileApps: true` on `@e2e-dev/core/engine`, which `web()` does; for any other engine a file `app.url` fails at config load, and `validateApp` is told with `fileApp: true`. `mobile()` and `desktop()` do not declare it.

- [#2175](https://github.com/e2e-inc/e2e/pull/2175) [`6ad8924`](https://github.com/e2e-inc/e2e/commit/6ad89248445f03b66038b7f0d299a3a002e73f99) Thanks [@satya164](https://github.com/satya164)! - An engine fixture is now `undefined` on a target whose engine doesn't have it, so a test with `device` can be run on web. Before, the run failed with `COLLECTION_ERROR`. The fixtures of every target are typed with the config's type as the third type argument: `test.extend<{}, {}, typeof config>()`, with `as const satisfies E2EConfig` on the config object. With `platforms` on a test, its fixtures are typed for the targets that run it.

- [#1903](https://github.com/e2e-inc/e2e/pull/1903) [`11de64b`](https://github.com/e2e-inc/e2e/commit/11de64b8bf4921436fe65c0c8dbe07b593a48187) Thanks [@luke-h1](https://github.com/luke-h1)! - `app.launchArguments` and `device.openApp({ launchArguments })` also take an object of argument name to string, number, boolean, or list of strings, such as `{ AppleLanguages: ['fr'], AppleLocale: 'fr_FR' }`. Write a name without its leading dash: `{ AppleLocale: 'fr_FR' }`, not `{ '-AppleLocale': 'fr_FR' }`. A dashed name in `app.launchArguments` fails at config load with `INVALID_CONFIG`, and one passed to `device.openApp` fails that call with `INVALID_ARGUMENT`. On iOS, `mobile()` sends each entry as `-name value`, and so does `desktop()` on macOS. On Android, each entry is an `am start` extra of the value's type: `--es`, `--ez`, `--ei` (`--el` beyond Java's `int`), `--ef`, or `--esa` for a list. An Android object fails when it holds one of Apple's arguments, such as `AppleLocale`, or a list that `am start` would change: an empty list, or an item that is empty, holds a comma, or ends in a backslash. A list of strings still goes to the launch command as given. `EngineAppInfo.launchArguments` stays a list of strings. An engine that declares `launchArgumentValues: true` receives an object in `EngineAppInfo.launchArgumentValues`; for any other engine an object fails at config load. `@e2e-dev/core/engine` exports the types, the shape check `checkLaunchArguments`, and `appleUserDefaults`, which spells an object as `-name value` arguments for an iOS or macOS app.

- [#2149](https://github.com/e2e-inc/e2e/pull/2149) [`7838198`](https://github.com/e2e-inc/e2e/commit/7838198caf77703bfa34d951cde2ed70a0d092d3) Thanks [@michal-e2e](https://github.com/michal-e2e)! - **Breaking:** Tests get a built-in `request` fixture for HTTP calls. `await request.post('/api/orders', { json: { sku: 'A1' } })` sends a request to a path on the app URL or to an absolute URL, shows in the report as a step, and stops at its `timeout` or the action timeout. It returns a `WebResponse`, the type `browser.waitForResponse` and `route.fetch()` return, which `@e2e-dev/core` and `e2e` now export too. It does not send the browser's cookies. A project fixture already named `request` now extends the built-in one, and one declared with its own type through `test.extend<{ request: ... }>({ request: ... })` no longer compiles, so rename it. An engine can no longer contribute a fixture named `request`.
